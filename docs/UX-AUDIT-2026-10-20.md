# Mobile & interaction audit — 2026-10-20

Scope: the live site (`gramshiksha-academy.vercel.app`), every role, desktop and
the iPhone 13 / iPhone SE viewports, plus a local seeded full stack for flows
that write data. Read-only checks ran against production; writes (enrollment,
lesson completion, notes, quizzes, uploads, approvals, invitations) ran locally
so production data stayed clean.

## Findings and fixes

| Finding | Cause | Fix |
| --- | --- | --- |
| 6 px horizontal page scroll on the public home/login screens at 320–390 px | `.hero-home` used a hard-coded `-20px` side margin while `main.container` drops to 14 px padding at ≤480 px | `main.container` now exposes `--page-pad` (20 px, 14 px at ≤480) and the hero uses `calc(-1 * var(--page-pad))` |
| 47 px overflow on the teacher dashboard at 320 px | "Students needing help" table was not scroll-contained | wrapped in the same `.table-scroll` region used by the admin dashboard (focusable, labelled) |
| "Why this book" input spilled out of its card on mobile | `gridColumn: 'span 2'` forced a second column in a one-column `auto-fit` grid | `gridColumn: '1 / -1'` spans whatever columns exist |
| Admin/teacher deep links such as `#/dashboard` and `#/progress` rendered student pages and produced 403s | the route switch had no role gate; the sidebar hid the links but bookmarks/history still reached them | role-scoped pages now redirect to the account's own home (student → dashboard, parent → parent, teacher/school admin → teacher, platform admin → admin); anonymous visitors go to the matching login page |
| Anonymous `#/parent` / `#/admin` landed on a login page that rejects those roles | redirect reused the student/teacher designated login | parent and admin now go to the generic `#/login` entry point |

The materials authoring form and its layout were left untouched as required.

## Phone PDF reader (follow-up)

A phone could sit on "Opening your book…" forever: the reader waited for the
iframe's `onLoad`, and Android Chrome has no inline PDF plugin for frames, so
the event never fired and the white overlay covered an empty panel. iOS can
also delay it on a slow connection.

- Small/touch screens now skip the iframe and show a focused panel with the
  book title, a same-origin **Open PDF** link (the phone's own viewer handles
  it) and **Save file**. Nothing is re-hosted and there is no external
  redirect.
- Desktop keeps the frame, gains an **Open PDF** action, and drops the loading
  overlay after six seconds if the engine never reports a load.
- The reader uses `(max-width: 768px), (pointer: coarse)` so phones in
  landscape still get the direct action.
- `e2e/reader.spec.ts` asserts the phone panel, the direct link's href/target,
  and the desktop frame.

Live check after deploy, 320 px: phone panel visible, zero iframes, 0 px page
overflow, and `/api/textbooks/140/open` returned `200 application/pdf` with
`Content-Disposition: inline`. Desktop showed the frame and the overlay
cleared after the timeout, with no console errors or API failures.

## Hardening pass (follow-up)

The phone PDF fix exposed the same class of failure elsewhere: a control that
looks fine on desktop but cannot complete its job on a small or touch screen,
or a loading state that never ends. These were reproduced before changing code.

| Finding | Cause | Fix |
| --- | --- | --- |
| Sign-up is impossible on an iPhone SE (320x568) | the register card was 667 px tall, centred at `top: -49 px` and `bottom: 617 px`; the fixed overlay had `overflow: visible` | `.auth-overlay` scrolls (`overflow-y: auto`), uses safe-area padding, and `.auth-card` uses auto margins so it centres only when it fits; body scroll is locked, Escape closes it |
| Tapping **Open offline** in My Downloads did nothing on phones | it created a blob URL and programmatically clicked an `_blank` anchor after an `await`, which is a popup without user activation (or a blank blob tab) | the saved file now opens in the current tab (`location.assign`); Back returns to My Downloads |
| Practice showed an endless skeleton when the API returned no questions | empty was treated as “still loading” (`!questions.length && !error`) | a separate loading flag; an empty set now shows “Nothing here yet” with Retry |
| A teacher with no students saw “Loading” forever; the same pattern existed in the admin user list | the empty array was used as the loading test | explicit loaded flags; empty results now say “Nothing here yet” |
| An expired token left a signed-in shell behind | `api.ts` cleared localStorage on `401`, but React kept the old `user` object, so every page kept firing requests that failed | a `gs:session-expired` event clears the React session; App also reconciles storage on mount because a fast child-effect 401 can beat the parent listener |
| iPhone home indicator covered the tab labels; notch/status areas were not reserved | the viewport meta lacked `viewport-fit=cover`, and tabbar/appbar/sidebar/viewer had no `env(safe-area-inset-*)` padding | added `viewport-fit=cover` and safe-area padding to the shell, drawer, tabbar, modal and viewer; main/footer bottom spacing now includes the inset |
| iOS zoomed the page whenever a login/doubt/material field was focused | controls inherited the 15 px body size; iOS zooms below 16 px | iOS-only `font-size: 16px` for `input`, `select`, `textarea` |
| The viewer sheet could extend under Safari’s dynamic toolbar | fixed `92vh` | `92dvh` with a `vh` fallback and `max-height: 100%` inside the safe-area-padded overlay |
